# Project Documentation

## Auto Ticket Classification using Flow Designer

### 1. Problem Statement

A school IT helpdesk receives multiple incident requests from students and teachers, including Wi-Fi issues, projector failures, password problems, and slow computers. Manual classification requires IT staff to review each request and select the appropriate category and subcategory.

This project automates that classification using ServiceNow Flow Designer.

### 2. Business Requirements

The system should:

1. Automatically classify IT tickets from their issue description.
2. Assign Category and Subcategory without manual intervention.
3. Support dependent choice logic between Category and Subcategory.
4. Send an automated email notification to the caller.
5. Store ticket information in a structured format.
6. Remain easy to maintain and extend.

### 3. Update Set

A Local Update Set named `Project Update Set` is used to capture the ServiceNow configuration.

Initial state:

`In progress`

Final state:

`Complete`

The completed Update Set can be exported as XML from ServiceNow.

### 4. Custom Table

Table label:

`Incident Workflow`

The table contains:

- Number — Auto Number
- Caller — Reference to `sys_user`
- Category — Choice
- Subcategory — Choice
- Short Description — String
- Description — String
- State — Choice
- Assigned Group — Reference to `sys_user_group`
- Assigned To — Reference to `sys_user`

### 5. Choice Configuration

Category:

- Network
- Hardware
- Access
- Performance

Subcategory:

- Wi-Fi
- Projector
- Forgot Password
- Slow Computer

State:

- New
- In progress
- On hold
- Resolved
- Closed

### 6. Dependent Choice Configuration

Subcategory is configured as dependent on Category.

```text
Wi-Fi            -> Network
Projector        -> Hardware
Forgot Password  -> Access
Slow Computer    -> Performance
```

### 7. Flow Designer Configuration

Flow name:

`Auto Classify School IT Tickets`

Trigger:

```text
Record Created
Table: Incident Workflow
Condition: Category is empty
```

Classification:

```text
Wi-Fi / WiFi / Network
    -> Network / Wi-Fi

Projector / Hardware
    -> Hardware / Projector

Password / Login / Forgot password
    -> Access / Forgot Password

Slow / Hanging / Slow Computer
    -> Performance / Slow Computer
```

### 8. Email Action

The flow uses the Send Email action after classification.

```text
To      : Caller -> Email
Subject : Your Request for the issue has been submitted.
Body    : Ticket confirmation message
```

### 9. Testing

Test 1:

```text
Short Description: WiFi not working in library
Expected:
Category = Network
Subcategory = Wi-Fi
```

Test 2:

```text
Short Description: Projector not turning on
Expected:
Category = Hardware
Subcategory = Projector
```

### 10. Security and Validation

The source project describes validation of:

- Mandatory field capture
- Auto-number generation
- Category/Subcategory accuracy
- User and group reference resolution
- Authorized access to ticket data

### 11. Deployment

After testing:

1. Open Local Update Sets.
2. Open `Project Update Set`.
3. Change state to `Complete`.
4. Save.
5. Export the Update Set to XML.

The XML export is generated by the user's ServiceNow instance and should be kept separately from this documentation.
